## Parser and identity corrections

- Corrected inverted item flags: the bit reader already unflips saved bits, so flags use one-based low-bit numbering. Historical broad bytime/noise counts from the old reader are invalid evidence.
- Corrected root item counts: socket children consume physical records without counting as additional roots in the saved page header. The shared stash now exposes all 5,040 declared roots, including all 147 on Miscellaneous.
- Enforced bit-reader boundaries instead of silently zero-padding the next item/page. Failure diagnostics retain bit positions.
- Prevented higher-tier base-code aliases from replacing canonical rows. Unique/set names use saved identity and compatible base families; runewords use ordered rune recipes and compatible item types. Raw runeword ID mapping is still unverified.
- Added resolved names while retaining base names for search and display. Browser verification found Eaglehorn in both the shared stash and magic-arrow character, displayed its Crusader Bow base, and returned named items through base-name search. See [interface evidence](inspector-2026-10-03.png).

Display tests prove limited real saved rolls for Blood Warp, Purgatory ethereal scaling, Uldyssian Energy scaling, Nightmare's Feast life-steal/splash scaling, and map tiers 1/2. Other values retain fallbacks. Rate displays do not claim computed character-context bonuses or full in-game tooltip parity.

## Bounded copy-based transfer support

The CLI supports persistent bank list, deposit, withdrawal, and recovery. Preview is the default; mutation requires `--experimental-write`. The inspector stays read-only. Known workspace game Save directories and the fixture library are protected, and development used disposable copies.

Serialization preserves original item bytes and edits supported location fields and root counts. No-op reconstruction preserves opaque source bytes. This is not a general field-backed serializer. Incomplete properties, ambiguous spans, unsupported geometry, overlapping placements, and ears are rejected. The supported stash grid is 10 columns by 15 rows.

A socketed Phoenix was deposited and withdrawn on a disposable Legacy stash copy: four runes remained attached, root counts changed by one, physical record counts changed by five, and item bytes matched outside the permitted location fields. A process-level CLI test also verified preview, deposit, list, withdrawal, count conservation, backup retention, and lock cleanup using a Bases copy.

Transactions use source/bank hash checks, parser-table fingerprints, per-bank/per-stash locks, flushed before-images, and a prepared journal before file replacement. Recovery rejects unknown external file changes and corrupted backups, and rechecks targets under locks. Tests cover process-interruption recovery. Directory metadata flushes, power-loss durability, and original file attribute retention are not established.
