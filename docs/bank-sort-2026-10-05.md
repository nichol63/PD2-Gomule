# Bank metadata sorting: October 5, 2026

The bank previously offered deposit order alone, even when searching a larger collection. The UI now provides `Stored order`, `Item name` and `Source`. CLI listing accepts `--sort stored|name|source`; omitting the option preserves stored order. Unsupported modes are rejected during argument parsing before the bank is read.

Both clients filter first and then use one pure metadata sorting helper. Name ordering compares lowercase display name, falling back to base name and code, then code. Source ordering compares filename, character name and page name, then the same item name/code keys. Text comparison is deterministic and independent of locale. Equal keys retain their original relative order. Every result is a new array containing the original item objects; sorting does not decode item bytes or change persisted bank order.

The UI retains a selected item by ID when its position changes. Changing sort invalidates the transfer preview and refreshes details through the existing generation guards. Destination containers and workspace item selection remain independent. The control retains its value through bank loads and library refreshes. An explicit `/bank-sort.mjs` route serves the helper as JavaScript with `Cache-Control: no-store`.

Parent independently checked the retained four-item QA bank. Stored order is Wolf Head, Wolf Head, Town Portal Book, Edge. Name order is Edge, Town Portal Book, Wolf Head, Wolf Head. Source order is the Amazon tome, both Bases Wolf Heads, then the freezing-arrow Edge. Both Wolf Heads retain their original ID order, including after filtering to Bases. Invalid CLI modes reject before a missing bank path is accessed. Bank bytes are unchanged; the local read-only server returns the expected module headers and control.

Seven independent tests cover immutable metadata sorting, deterministic comparison, source-key order, invalid CLI modes, real fixture helper/CLI/UI parity, selected-ID/sort retention through load and refresh, preview/detail invalidation, and the no-store module route.
